# macOS Apple Silicon port

## Scope

Develop in the `DurkaEbanaya/win10-task-manager-on-linux` fork (`feat/macos-arm`,
with subsequent sensor work on `feat/macos-telemetry`),
preserving Linux functionality and Mission Center attribution. Propose changes upstream
after the port is ready, not during this initial bring-up.

The first milestone (native Win10-style egui/Metal interface) was visually approved
by the user. Development now includes a live macOS backend; supported capabilities
and remaining gaps are listed below. This is not a claim of full Linux parity.

## Architecture

- Reuse `mc-core`, `mc-graph-core`, `mc-graph` and the egui UI.
- Keep OS-specific collection off the UI thread and preserve bounded events and
  the latest-snapshot hand-off.
- `platform-macos` implements magpie's existing platform interfaces. Do not adapt Linux `/proc`, sysfs, netlink, systemd or DRM
  collectors by inventing equivalent values.
- Unavailable telemetry must stay unavailable, rather than becoming zero.
- Preserve the default OpenGL renderer on Linux; prefer wgpu on macOS when compiled in.

## Milestones

1. Native ARM GUI: compile, test, render synthetic data on a real Mac, verify
   Retina sizing and basic window interactions. Document reproducible commands.
2. Live CPU, memory and process collection with permission-aware process actions.
3. Overall disk/network statistics, application identity and battery information.
4. Investigate Apple GPU, temperature/power counters and launchd services separately.
   Availability and permissions require measurements on supported macOS versions.
5. Application bundle, CI artifacts, signing/notarization and upstream proposal.

## Development machine

User-provided MacBook Air M5, arm64, 16 GiB RAM. Initial SSH checks reported macOS
27.2.1 (26B131), model `Mac17,3`. Apple Command Line Tools and Homebrew were already
installed. Rust 1.96.1 (minimal profile plus rustfmt/Clippy) and CMake were installed
with user approval. No passwords or machine access configuration belong in this repository.

## Live capabilities and limitations

| Area | Native source / supported behavior | Unavailable / caveat |
| --- | --- | --- |
| CPU | Mach per-core tick deltas, utilization, kernel share, uptime, process enumeration; public default-processor-set system thread count; optional IOReport E/P active-residency average clocks; complete top Mach-port aggregates | Not instantaneous per-core frequency; unknown state/table mappings and idle clusters have no clock; CPU power unknown; Mach ports are not Windows Handles or open files |
| CPU topology | `hw.physicalcpu` and optional `hw.perflevel*` physical/logical counts and L1I/L1D/L2 sizes | Kernel-reported aggregate groups, not per-graph CPU affinity; no guessed SLC/L3 capacity or catalog clocks |
| Memory | Mach VM statistics, sysinfo Darwin available estimate, swap, wired/compressed pages; native pressure level (normal/warning/critical) | Usage estimate is not Activity Monitor's Memory Used or a pressure percentage; no DIMM/SPD inventory |
| Processes | libproc PID/start identity, CPU deltas, resident bytes, disk-I/O deltas, owner, executable, state and threads | SIP/permissions omit unreadable entries; no args, per-process swap/network/GPU |
| Actions | SIGTERM/SIGKILL as the logged-in user, never sudo | PID 0/1 and group signals rejected; kernel permission checks still apply |
| Apps | Group executable paths under `.app/Contents/MacOS/` | Icons/localized bundle display names not yet collected |
| Volumes | Browsable local mounted volumes, capacity, available space | APFS shared container capacity is not additive; volume is not a physical disk |
| Disk I/O | IOBlockStorageDriver cumulative bytes, elapsed-time throughput | Busy time/latency/SMART/eject unavailable; no summed-process substitute |
| Network | Interface counters, elapsed-time rates, addresses, IOKit class and getifaddrs flags | No guessed en0 Wi-Fi identity, SSID/link speed or per-process attribution |
| GPU | IOAccelerator identity, renderer/tiler/device utilization; separate driver system allocation/in-use bytes when exported | Driver-dependent, explicitly partial; driver counters are not VRAM capacity or resident usage; no per-process data or inferred memory budget |
| Battery | AppleSmartBattery registry charge, voltage, current-derived power, cycles/state; optional SMC battery temperature and driver time estimates | Only present fields; normalized capacity is never labeled mWh or battery health; unavailable/sentinel times stay unknown |
| Services | `launchctl list`, current bootstrap namespace, read-only | Not a complete system inventory; enablement unknown, actions/logs disabled |
| Sensors | Optional unprivileged IOHID thermal events and read-only AppleSMC temperature keys, exposed in Cooling with original labels | Undocumented, hardware-dependent; no guessed CPU/GPU hotspot mapping, no fan/control writes, calibration channels excluded; no fan inferred on a passive Air |

Collection runs on daemon workers, not in the GUI. The macOS client creates its
process-control IPC in an atomically created 0700 directory and cleans it up on exit.
No password, SSH configuration, process snapshots or desktop capture is committed.
Native bundles are ad-hoc signed, not Developer ID signed/notarized. A distributable
notarized release requires the owner's Apple signing credentials and separate consent.

`support/macos/build.sh` builds both matching binaries into `Task Manager.app`;
`support/macos/verify.py` records five real snapshots in an ignored temporary fixture
directory, checks essential native telemetry and removes them, without uploading data.

See the macOS section of `README.md` for build and run commands.

## Bring-up verification (2026-11-16)

On the development Mac, Rust 1.96.1 successfully built an `arm64` Mach-O GUI with
`--no-default-features --features wgpu,production-logging`. A native window run with
`WGPU_BACKEND=metal --synthetic 300 --no-config --bench-seconds 8` exited successfully;
its `--stats-file target/ui-snapshots/macos-native-smoke.txt` confirmed both UI frames
and incoming fixture snapshots. This was a functional smoke test, not an idle or
release performance benchmark.

The Mac passed workspace/all-target Clippy with warnings denied, all tests for
`mc-core`, `mc-graph-core`, `mc-graph`, `mc-ui`, wgpu-only app tests and socket tests.
The UI suite includes actual Metal offscreen renders, 2× scale, pixel probes and
simulated tab/menu/resize interactions. `target/ui-snapshots/hidpi-2x-900x600.png`
was copied back for visual review and showed the expected bundled-font interface.
Snapshots stay in ignored build output, not in source control.

Linux workspace tests and the same pinned Clippy command also passed at bring-up. macOS CI
intentionally excludes Linux hardware-helper/daemon and nested-compositor tests;
Linux CI remains responsible for those. These checks do not yet prove native
trackpad dragging, maximize/minimize behavior or the user's preferred desktop scale:
the user subsequently checked the native window and approved its appearance.

## Live development verification (2026-11-16)

An initial five-snapshot, unprivileged capture on the M5 returned 10 per-core CPU
samples, 17,179,869,184 bytes RAM and 434 readable processes in the inspected snapshot
(747 enumerated PIDs). All 434 readable entries had valid CPU, resident-memory and
disk-I/O deltas after warm-up; global thread/handle totals correctly remained unknown.
These are observations from that capture, not fixed expectations or performance data.
A later capture read Apple M5 GPU utilization, physical `disk0` counters and 543
launchd jobs in the SSH bootstrap namespace. Raw data remains only in ignored fixtures.
The first battery dependency did not detect this Mac's battery and was removed in
favor of typed, optional AppleSmartBattery registry reads.

The initial preview CI built/tested successfully but its final shell check failed
because `rg` was absent from the runner. The live workflow no longer depends on it;
final CI and bundle verification must be recorded after the live implementation passes.

The live backend subsequently passed native tests for counter warm-up, CPU/RAM/own
process readings and SIGTERM/SIGKILL applied only to test-owned `/bin/sleep` children.
The M5 passed pinned Rust 1.96.1 Clippy (workspace/all targets and native daemon),
the GUI/model suites including Metal snapshots/probes, app and socket tests. Linux
workspace tests and the Linux backend's 101 tests plus one protocol test passed.
The ad-hoc signed bundle passed `codesign --verify --deep --strict` and the five-snapshot
integration check. A six-second **live** native window smoke applied 10 snapshots and
exited normally; it is functional evidence, not a performance benchmark.

## Follow-up research: user projects

The user accepted the live build as an alpha and disconnected the physical Mac.
That alpha subsequently passed macOS CI and was deployed on the M5. The later
telemetry expansion is being validated separately on the reconnected physical Mac.

- [Aida128](https://github.com/DurkaEbanaya/Aida128/tree/c602d550bfaa504dbbc2940f6eac8436abce1bed)
  (`Sources/BenchmarkCore/BenchmarkCore.cpp`, MIT) demonstrates runtime
  `hw.perflevel*` topology and per-group cache queries. The port independently
  implements these queries and displays available groups without assuming their
  order maps to Mach logical-CPU ordinals. Optional wire fields retain old fixture
  compatibility. Its M5 clock/memory/SLC catalog is explicitly mapped/experimental,
  so it is not a live sensor source and is not imported as measured telemetry.
- [1700stats](https://github.com/DurkaEbanaya/1700stats/tree/2fc15bd3338ae3f34d358dae6d988ee6cd162622)
  is an Intel-only Hackintosh kernel extension using APERF/MPERF and x86 thermal
  MSRs. Those sources cannot run on Apple Silicon. No kext, source code, binary,
  privileged helper or security-setting changes are imported; the repository has
  no declared license. Its validity/baseline discipline agrees with this port's
  explicit unknown values but does not unlock M5 sensors.

Neither repository supplies an unprivileged Apple Silicon live frequency,
package-power or thermal collector. These gaps remain explicit rather than
being filled with nominal M5 specifications. No changes were made to either
reference repository.

The first live CI on macOS 15 exposed an older VM-statistics revision: the
kernel returns a shorter structure than the latest libc definition. Validation
now requires the complete prefix through `external_page_count`, the last field
actually read, rather than equality with the newest structure size. A regression
test covers complete older revisions and rejected short reads. Available memory
uses one VM sample and the sysinfo estimate `free + inactive + purgeable -
compressor` (saturating and bounded by total RAM); tooltips state that formula.

## Optional sensor expansion

Read-only reference research used macmon 0.12.0 (MIT, exact revision and notice in
`docs/PROVENANCE.md`). TMOG's public feature description was reviewed; its private
implementation and assets are not incorporated. No sudo or security changes are required.

A five-snapshot development capture on the M5 returned 99 HID/SMC temperature
channels (not 99 independent components), native pressure level 1, driver GPU system
allocation/in-use counters and active CPU complex clock averages. One observed
sample reported about 2130 MHz for Super and 1675 MHz for Efficiency. These are
time-varying observations, not nominal frequencies, accuracy calibration or a benchmark.
The M5 exposes 8 ECPU active states and 19 PCPU active states matching the respective
pmgr tables. The GPU's 16 states do **not** match its 13 table entries, so its clock
is deliberately unavailable. CPU/ANE energy counters did not provide reliable
deltas on this macOS version and are not turned into apparent zero-watt sensors.

HID registry identities and SMC FourCC keys remain visible. Calibration channels
are filtered, invalid/out-of-range values are absent, and raw channels are not
renamed as a CPU/GPU hotspot without a verified mapping. SMC only issues read,
key-index and key-info commands; no fan, voltage, performance or power controls exist.

The expansion passed Rust 1.96.1 Clippy with warnings denied on Linux and the physical
M5 (both GUI and macOS daemon), full Linux workspace/backend tests, and Mac model/UI
tests including Metal renders. Seven native backend tests cover VM ABI revisions,
counter validity, owned-child signals and SMC payload/temperature decoding. The
ad-hoc signed release bundle passed a five-snapshot live integration check. A
subsequent short capture verified runtime group cache sizes and 96 readable values
out of 99 discovered thermal channels; unreadable values remained unavailable.

## CPU field completion

- **Speed (active avg.)** displays the measured IOReport cluster averages in the
  explicitly listed group order, rather than leaving Speed empty or presenting an
  arbitrary cluster as a machine-wide instantaneous clock. No single-value clock
  graph or nominal frequency is inferred from these heterogeneous groups.
- **Threads** uses `processor_set_default` + `processor_set_statistics` with
  `PROCESSOR_SET_LOAD_INFO`. This reports the system thread count without reading
  individual tasks and removes the SIP-driven gaps of the earlier libproc sum.
  Returned size/status are validated and both Mach port references are released.
- **Mach ports** occupies the old Handles position on Darwin, as agreed with the
  user. Its hover tooltip explains the distinction from Windows Handles, files
  and unique kernel objects; no extra rows or windows are added. An unprivileged
  bounded Apple `top` sample is aggregated every five seconds. Incomplete reads
  clear the value to unknown. `kern.num_files` remains a separate wire field,
  not displayed as Handles. See `docs/hardware-monitoring.md` for read-only
  probes, coverage validation and limits. Linux Handles is unchanged.
- **Sockets**, **Virtualization**, **Virtual machine** use exact-size runtime
  `hw.packages`, `kern.hv_support`, `kern.hv_vmm_present`. Hypervisor framework
  support does not imply that a VM is running, or that this OS is a guest.
- **Base Speed** and **L3 cache** explicitly say *Not reported by macOS* when
  their sysctls are absent. Neither a maximum DVFS state nor Apple system-level
  cache is relabeled as CPU base frequency/L3. The physical M5 returned one package,
  hypervisor support 1 and guest flag 0; its base-frequency/L3 queries were absent.
